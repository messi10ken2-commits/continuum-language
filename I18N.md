# Base language localization

Base language and target language are separate application concepts. `base-language.mjs` owns supported base languages and UI catalogs. `languages.mjs` continues to own course target languages. Do not use a target-language ID to choose interface text. The server imports the same base-language registry for preference validation.

This is an incremental migration, not complete platform localization. Many screens, assessments, teacher tools and lesson fields still use English. Authored translations are drafts awaiting linguistic review; no human review is implied. No runtime translation service is used.

Educational text is authored in `lesson-localizations.mjs`, keyed by stable lesson ID and base language. Localized records overlay presentation fields only; lesson IDs, target-language examples, answer choices, correct-answer indexes, grading, CEFR metadata, and saved history continue to come from the original course modules. This lets reviewers approve grammatical terminology and explanations without editing assessment logic.

Missing registered UI keys and supported lesson fields fall back to English. Lesson screens show a fallback notice when educational fields are missing. Run `npm run i18n:report` for coverage counts or `npm run i18n:report -- --details` for missing registered keys, lesson fields and literal JSX candidates. The source audit includes text and accessibility attributes; dynamic strings and imported data require separate review. Target-language examples in that audit must not be translated indiscriminately. The report exits unsuccessfully when a registered UI catalog is incomplete; educational gaps are reported for localization planning. A zero missing-key count does not mean the whole application is translated.

Question feedback entries match both `sourcePrompt` and `sourceNote`, not the question's array index; shuffled variants keep their original grading data. Vocabulary entries match `term`, rule steps match `source`, and example translations match `target`. Only explicitly supported presentation fields are overlaid. Tables match `sourceCaption`; headers match `source`; explanatory cells match `row`, `header` and `source`. Only columns allowlisted in `reference-schema.mjs` permit cell translations. Conjugated forms and other target material stay unchanged. Original headers are retained for speech behavior even when displayed headings are translated.

Review workflow: author localized explanations independently of course modules, have a language educator check terminology and examples, and record `review: {status: 'reviewed', reviewer: '...', date: 'YYYY-MM-DD'}` on the locale record after actual review. Missing metadata means draft. Review metadata is editorial and does not currently gate rendering. Recheck translations whenever their source text changes; question feedback and rule steps automatically fall back if their source match changes.

To add a base language:

1. Add its metadata and complete UI catalog in `base-language.mjs`.
2. Add its catalogs in the domain-specific `*-messages.mjs` modules; server validation follows the shared registry automatically.
3. Add reviewed lesson entries incrementally in `lesson-localizations.mjs`.
4. Run `npm run i18n:report`, `npm run test:i18n`, `npm test`, and `npm run build`.

For local account-backed development, run `bash scripts/dev-local.sh`. It starts an isolated PostgreSQL Docker container on loopback port 55432, builds the client and starts the app with its own development database URL. No externally supplied `DATABASE_URL` is needed for this command. Docker must be available. This database is for development only; do not store real learner data there or use its trust authentication in production. Container data preservation across cloud environment snapshots has not been verified.

## Validation and remaining migration

Validated in this workspace:

- `npm run test:i18n`: nine unit checks, authenticated preference API checks for learners and teachers, six-language reference rendering, and grading-input preservation across all course lessons.
- `node curriculum-render.test.mjs`: 15 level roadmaps, 267 lesson introductions and 267 exercise screens.
- `node multilingual-api.test.mjs`: independent assessments, histories and drafts for four target languages.
- `node --test mistake-feedback.test.mjs`: all three existing feedback tests.
- `npm run build`: passes, with the existing large-bundle warning.
- Real PostgreSQL: registration, language preference changes, logout/login restoration and health request.
- `node scripts/check-base-language-migration.mjs`: a separate temporary PostgreSQL database simulates the previous users schema; repeated migrations preserve IDs, password hashes, sessions, practice history, teacher sharing/notes, an active assessment and the saved base language.
- `node scripts/check-base-language-browser.mjs` against the local development app: Japanese registration/onboarding; failed-save consistency; translated success messages; independent target selection across reload; delayed-save/logout isolation; login persistence; Japanese vocabulary and a complete Spanish exercise/save flow. Requires Chromium and creates a synthetic account. Server restart persistence was also verified separately.

The default `npm test` now runs every root `*.test.mjs` file with bounded concurrency: all 156 checks pass. Eight earlier failures were stale assumptions about specialist checkpoint extensions, transfer-task identity, assessment skill ordering, workshop scope and explicit teacher language permissions. The assertions now follow the existing contracts; access checks, rate limits, course material and scoring were not relaxed. `npm run check:release` runs the full suite, build and coverage report. `npm audit --omit=dev` reports no vulnerabilities after updating the locked `source-map-js` dependency to 1.2.2.

Current coverage is 165 registered UI messages in all six base languages and three Spanish-target lesson overlays, including food vocabulary. The audit still identifies 671 literal JSX candidates for triage and about 8,000 missing educational fields per non-English base. These counts do not include every dynamic string or external content field. Assessment pages, teacher workflows, profile review, speech/script reference, review pools and many roadmap descriptions still need migration. User-authored notes and teacher profile prose must not be automatically rewritten. Lesson-specific mistake explanations and assessment prompts also retain their authored source text where not localized. Functional validation is green, but this must be described as an incremental translation preview, not a fully localized six-language release. No production deployment has been performed.
