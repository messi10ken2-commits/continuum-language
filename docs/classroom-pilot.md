# 少人数向けの授業・復習の試行運用

このリリースで使える流れは、**接続 → 連絡 → 日時提案 → 承認 → 通話参加 → ノート → 課題 → 復習 → 提出 → フィードバック**です。現在の予約は `pilot-v1`。Continuum内の料金徴収、返金、教師への送金は有効になっていません。

## 使い方

| 担当 | 操作 |
|---|---|
| 生徒 | 「授業」→「先生を探す」で公開済みの先生を選び、言語別の共有に同意して接続します。既存の先生には「アカウント」の共有コードを直接渡す方法も使えます。 |
| 教師 | 初期プロフィールを設定し、公開を希望する場合は審査へ提出します。共有コードはホーム画面から入力できます。接続した生徒と共有言語は生徒一覧で確認できます。 |
| 両者 | 「授業」内で相手と言語を選び、メッセージで相談します。チャットはその二人・その言語ごとに分かれています。 |
| 両者 | 表示タイムゾーンを確認し、テーマ・日付・時刻・授業時間を入力して日時を提案します。相手が承認すると確定します。 |
| 教師 | 確定した授業の詳細に、既存のGoogle Meet・Zoom・Teams・Jitsi・WherebyのHTTPS参加リンクを保存します。リンクの発行は通話サービス側で行います。 |
| 両者 | 「授業に参加する」から通話サービスを開きます。Continuumが通話の録音や実際の出席判定をする仕組みは含みません。 |
| 教師 | 開始時刻を過ぎた確定授業を終了にし、共有ノートや課題を作成します。終了後も「授業履歴」から開けます。 |
| 教師 | 課題のタイトル・内容から復習レッスンが提案されます。手動で別の適切なレッスンを指定することも、記述課題だけを送ることもできます。明確な対応がなければ無関係なレッスンには飛ばしません。 |
| 生徒 | 「課題」から指定されたレッスンを開いて練習し、解答・取り組んだ内容と、必要に応じて課題作成後に完了した指定レッスンの結果を提出します。 |
| 教師 | 提出内容を確認して具体的なフィードバックを送ります。生徒は課題画面で読み返し、再度取り組んで提出できます。 |

## 日時と変更

- 保存する時刻はUTC。画面には選択したIANAタイムゾーンで表示し、表示設定はアカウントごとに端末へ保存します。
- 夏時間で存在しない時刻は選べません。同じ時刻が2回現れる場合はUTCからの時差を明示して選択します。
- 提案は5分後以降、180日以内。授業時間は15〜120分の範囲です。現在の画面では25・30・45・50・60・90分を選べます。
- 承認前の提案は枠を確保しません。承認時に先生・生徒の確定授業との重複を再確認します。二人を同じ順序でロックすることで同時承認の競合を防ぎます。
- 確定した授業の日時変更は、別の提案を作って相手が承認する方式です。新しい日時が承認されるまでは元の予約が有効で、承認時に入れ替わります。
- 試行期間のキャンセル料はありません。先生・生徒のいずれも理由を記入してキャンセルできます。
- 外部カレンダーや他サービスの予約との自動照合はしません。提案の承認前に自分の予定も確認してください。

## 共有する情報

- 教師の学習記録・ノート・課題は、生徒が共有した担当言語だけに制限します。
- 通常の共有授業ノートは、生徒が同じ言語の共有を許可した他の教師にも学習記録として表示されます。私的なメモ欄ではありません。
- チャット・予約詳細・通話リンク・課題の提出文・フィードバックは、その教師と生徒の間で共有します。他の教師は閲覧できません。
- 自主学習の共有をオフにすると、教師向けの課題画面でもレッスンの点数・練習履歴は非表示になります。生徒が明示的に提出した文章と教師のフィードバックは、授業のやり取りとして残ります。
- 言語の共有を外すと、その教師は対象言語のチャット・授業・課題にアクセスできなくなります。未終了の今後の予約も同じトランザクションでキャンセルします。生徒側には自分の履歴が残ります。
- 学習者名・メッセージ・ノート・課題・提出文を画面の表示言語へ自動翻訳することはありません。
- 通知はアプリ内です。チャットは表示中に約8秒、授業情報は約15秒で確認し、ナビゲーションにも対応待ち件数を表示します。メール・プッシュ通知は含みません。

## 管理画面

既存のオーナー専用「管理」内に「授業の運用管理」を追加しました。直近100件の予約の状況確認、理由付きの試行授業のキャンセル、日時提案・承認・変更・課題等の操作履歴を確認できます。通常の教師や生徒には公開しません。管理画面の授業一覧は通話リンクやチャット本文を返しません。

`class_events` に操作者・対象授業/課題・操作・理由を保存します。プロフィールの審査履歴は既存の専用履歴を使用します。会話や提出文をサーバーログへ出力することはありません。

## 有料授業を始める前の次の実装

以下は未実装です。試行用のキャンセル無料ルールを、そのまま有料授業の契約条件として扱いません。

| 確定・実装が必要な項目 | 次に決める内容 |
|---|---|
| 商品・価格 | 単発かパッケージか、通貨、価格、手数料、販売主体 |
| キャンセル・欠席 | 締め切り、変更回数、双方の欠席・中断時の扱い |
| 返金 | 全額/一部の条件、判断権限、理由・処理履歴 |
| 決済接続 | 決済事業者・本番アカウント、署名検証付きWebhook、冪等処理、支払い成功後の予約確定、売上台帳との突合 |
| 教師への支払い | 対応国・通貨・受取方法、必要な確認、手数料負担、授業完了から支払いまでの期間、失敗時の再処理 |
| 運営 | 条件の版管理と同意、返金・送金操作の権限、監査履歴、サポート対応 |

現在はAPIとデータベースの両方で授業金額を0に固定しています。支払い画面、返金済み表示、教師残高などの仮実装は置いていません。決済接続と運用条件を整えた別リリースで有料化します。

## 実装と検証

- `classroom-api.mjs`: 言語別の接続、チャット、予約、ノート、課題、運用履歴。既存の認証・所有者権限を使用。
- `class-time.mjs`: IANAタイムゾーンと夏時間の解決。
- `ClassWorkspace.jsx`: 教師・生徒共通の授業導線。教師のホームでは生徒選択と言語選択を保持。
- `classroom-copy.mjs`: 英語・日本語・スペイン語・ポルトガル語・中国語・フランス語のUI。
- 既存の共有ノートと `class-practice.mjs` を継続利用し、手動で選んだ復習レッスンを優先。
- スキーマは起動時に追加し、既存のアカウント・学習結果を削除しません。

検証コマンド:

```sh
npm run test:classroom
node teacher-language-api.test.mjs
node profiles-api.test.mjs
node speaking-api.test.mjs
npm test
npm run build
CHROMIUM_BIN=/path/to/chrome-headless-shell npm run test:classroom:browser
```

API検証は隔離したPostgreSQL互換データベースを使用します。ブラウザ検証は先生用と生徒用の別コンテキストを使い、実際のレッスンの全問完了・提出・フィードバックまで操作します。授業時間の経過だけは検証用データを調整し、外部の通話接続や料金徴収は実行しません。

## 予約提案・通話ボタンの更新

- 新規予約と日時変更の提案は生徒のみが行い、先生が承認します。先生はチャットで候補日時を相談できます。既存の先生発の未承認提案は引き続き相手が回答できます。
- 承認時に予約専用のランダムなJitsi URLを保存し、双方の「授業に参加」ボタンから開けます。URLのコピー・貼り付けは不要です。日時変更が承認されると新しい予約に別のルームを用意します。
- 先生が先にルームを開始してください。公開Jitsiは主催者の外部アカウント認証を要求する場合があり、生徒は主催者を待ちます。Continuumの認証と外部通話サービスの認証は別です。外部ルーム自体をContinuumの権限で閉じることはできないため、招待URLを第三者に共有しないでください。
- 既存のリンク未設定の確定予約では先生の「通話ルームを用意する」ボタンで準備できます。
- Google Meet等の既存リンクへの手動変更も残しています。Google Meet APIによる自動作成やGoogle OAuth連携は未実装です。PreplyやAmazingTalkerの独自通話室も生成しません。
