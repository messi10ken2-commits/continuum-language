# 少人数向けの授業・復習の試行運用

現在の流れは **接続 → 連絡 → 公開空き枠から即時予約 → 通話参加 → ノート → 課題 → 復習 → 提出 → フィードバック** です。新しい予約のルールは `pilot-slots-v2`。既存の予約は元の版を保持します。料金は0で、決済・返金・教師への送金は未接続です。

## 最初の設定

| 担当 | 操作 |
|---|---|
| 教師 | プロフィールを設定し、公開する場合は審査へ提出します。生徒から共有コードを受け取って接続する方法もあります。 |
| 生徒 | 「授業 → 先生を探す」で公開中の先生を選び、言語別の共有に同意して接続します。既存の先生には「アカウント」の共有コードを直接渡せます。 |
| 両者 | 「授業」で相手と言語を選び、メッセージで相談します。チャットはその二人・その言語ごとに分かれています。 |

## 毎週の基本スケジュール

教師の「授業 → スケジュール」には次の4項目があります。

| 項目 | 用途 |
|---|---|
| カレンダー | 日・週表示で、予約可能・予約済み・日時変更提案・休暇を確認。色付きの枠を押すと詳細を開けます。空白の時刻を押すと単発枠を追加できます。 |
| 毎週の時間帯 | 月曜〜日曜それぞれの授業の有無と開始〜終了時刻を保存。同じ曜日に最大4つの時間帯を設定できます。 |
| 単発の追加枠 | 基本スケジュールとは別に、その日だけの空き枠を追加。日付と時刻をカレンダー・時刻ボタンから選びます。 |
| 休暇・休憩 | 特定の日だけ対応できない期間を指定。時間指定または終日の複数日休暇に対応します。 |

- 基本スケジュールには終了日や「何週間」の指定はありません。変更するまで毎週続きます。例えば月曜19:00〜24:00なら、その時間帯が毎週の基本になります。
- 基本設定はそのスケジュール専用のIANAタイムゾーン、授業時間、授業間の休憩を持ちます。カレンダーの表示タイムゾーンとは別です。表示時刻を変えるだけで、保存した基本時間が変わることはありません。
- 時間帯内に完全に収まる授業枠を、授業時間＋休憩の間隔で用意します。最後の授業後の休憩は不要です。終了24:00は翌日0時を意味します。
- 内部では60日先までの予約可能な枠を用意し、先生または生徒が予定・空き枠を確認すると先へ延長します。有限の繰り返しを何度も登録し直す必要はありません。
- 夏時間でも同じ現地時刻を保ちます。切り替えで重複・消失する時刻や授業時間が変わる枠は自動生成から除外し、必要なら単発枠でUTCオフセットを選んで登録します。
- 基本スケジュールの変更・無効化は、古い未予約の定型枠を非公開にして新しい枠を作ります。確定済みの授業は取り消し・移動しません。単発枠も勝手には消しません。
- カレンダーから定型の1枠だけを削除しても、翌日の延長処理で同じ枠が復活しないようにしています。定型を再保存した場合は新しい基本設定として扱います。期間の例外には休暇・休憩を使ってください。
- 休暇を設定すると重なる枠は予約対象から外れ、解除すると再び予約できます。確定済みの授業は残るため、必要な変更は生徒と相談して個別に行います。
- 終日の休暇は選択した開始日と最終日の両方を含み、最終日の翌日0時で終了します。
- 独立した教師側の「課題」メニューは廃止し、「授業」内の「課題」ボタンに統合しました。既存の課題・提出・フィードバックは保持しています。

## 予約・授業・課題

1. 生徒が先生の公開枠を選ぶと、承認待ちなしで予約を確定します。先生と生徒の予定、公開状態、休暇、担当言語の共有を再確認します。
2. 生徒の日時変更は別の公開枠を選ぶ即時確定方式です。先生からの日時変更には理由と生徒の承諾が必要で、承諾までは元の予約を維持します。提案は枠を確保せず、承諾時にも重複・休暇・公開状態を確認します。
3. 予約には専用のランダムなJitsiルームへの参加ボタンが付きます。先生が先にルームを開始してください。外部サービス側で主催者の認証を求められる場合があります。
4. 先生は必要に応じてGoogle Meet・Zoom・Teams・Jitsi・Wherebyの既存HTTPSリンクへ変更できます。Google Meet自動発行・Google OAuth・Preply等の通話室生成は未実装です。
5. 開始時刻を過ぎた確定授業を先生が終了にし、共有ノートや課題を作成します。実通話の録音・出席判定・欠席検知は行いません。
6. 課題の文面から適切な同一言語の復習レッスンを提案し、先生が手動指定することもできます。明確な対応がなければ無関係なレッスンには誘導しません。
7. 生徒がレッスンを練習して文章・結果を提出し、先生が具体的なフィードバックを返します。生徒は再度取り組んで提出できます。

保存時刻はUTC。予約は5分後以降で、単発枠は180日以内・15〜120分です。ユーザーを一定の順序でロックし、予約済み枠の一意制約も使って同時予約を防止します。外部カレンダーとの同期はありません。

## 実績とキャンセルの影響

教師ホームに要約、「授業 → 授業の実績」に詳細を表示します。期間は過去7・30・90日。

- 完了した授業数・指導時間、累計、過去7日間の授業数、今後の確定授業数、授業を受けた生徒数を表示。指導時間は完了扱いの授業の予定時間であり、実通話時間ではありません。
- 実績の割合は期間内に作成または操作された確定予約が母数。先生都合キャンセルを件数・割合に算入し、先生都合でキャンセルしなかった割合（継続実施率）を下げます。生徒都合・提案の辞退・管理者の取り消しは先生のキャンセルに含めません。
- 先生起案の日時変更は、生徒が承諾した場合だけ先生の変更率に算入します。先生のキャンセル後はその枠を非公開にします。生徒がキャンセルした枠は、現在の基本設定で有効なら再び予約可能になります。
- 金銭的な罰則、ランキング変更、アカウントの自動停止はありません。
- 返信率は生徒の最初のメッセージから先生の次の実メッセージまでを1件とし、24時間以内かを集計。連投とシステム通知は件数を増やしません。未返信は24時間後に算入し、データがなければ「—」です。
- 決済未接続のため、収益・利益・受取見込みを捏造せず、未受領・未対応と明記します。

## 共有範囲と管理

- 教師は生徒が共有した担当言語の学習記録・ノート・課題だけにアクセスできます。
- 通常の共有ノートは、生徒が同じ言語の共有を許可した他の教師にも学習記録として表示されます。私的なメモ欄ではありません。
- チャット・予約詳細・通話リンク・課題の提出文とフィードバックはその二人だけに共有します。他の教師は閲覧できません。カレンダーも本人の教師アカウントに限定します。
- 自主学習の共有をオフにすると、教師の課題画面でも点数・練習履歴は非表示になります。明示的な提出文と先生のフィードバックは残ります。
- 言語共有を解除すると先生は対象言語へアクセスできなくなり、未終了の今後の予約も同じトランザクションでキャンセルします。生徒には自分の履歴が残ります。
- ユーザーが書いた名前・メッセージ・ノート・課題を自動翻訳しません。画面のUIは6表示言語に対応します。
- 通知はアプリ内です。メール・プッシュ通知は未実装です。外部通話URLの所持者をContinuumの権限だけで制限することはできません。
- オーナー専用の「管理 → 授業の運用管理」で直近の予約、理由付きの取り消し、操作履歴を確認できます。管理一覧にチャット本文や通話リンクは返しません。

## 有料授業の前に必要な実装

決済画面・返金・送金・売上台帳は未実装。APIとDBで料金0を維持しています。販売主体、価格・通貨・手数料、キャンセル/欠席/返金条件、決済事業者、署名付きWebhook、決済と予約確定の整合性、教師の受取方法・本人確認・送金条件、管理者の権限と監査を決め、別リリースで実装します。

## 実装と検証

主な追加実装: `classroom-api.mjs`、`teacher-schedule-api.mjs`、`weekly-schedule.mjs`、`WeeklySchedule.jsx`、`TeacherWorkspace.jsx`、`CalendarDateTimePicker.jsx`。既存アカウント・学習結果を削除せず起動時にスキーマを追加します。

```sh
npm run test:classroom
node teacher-language-api.test.mjs
npm run build
CHROMIUM_BIN=/path/to/chrome-headless-shell npm run test:classroom:browser
```

APIは隔離DBで、定型の永続性・延長・夏時間・休暇の上書き/解除・同時予約・既存予約の保持・共有制限を検証。ブラウザは先生と生徒の別コンテキストで、曜日別時間設定から予約、実レッスンの全問完了、提出とフィードバックまで確認します。時間経過のみ検証用データを調整し、本番の試験アカウント作成、外部通話、料金徴収は行いません。
